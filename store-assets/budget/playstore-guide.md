## 0. AdMob 광고 설정 (먼저)

앱 하단에 **Google AdMob 배너**가 들어가 있어요. 실제 광고 ID를 넣지 않으면 Google 테스트 광고로 빌드되고, 업로드 워크플로는 테스트 광고 출시를 막으려고 멈춰요.

1. https://admob.google.com → **앱 → 앱 추가**
   - 플랫폼 **iOS** → "앱이 지원되는 앱 스토어에 등록되어 있나요?" → **아니요** (출시 후 스토어와 연결) → 앱 이름 `한지붕 가계부`
   - 같은 방법으로 **Android** 앱도 하나 더 추가
2. 각 앱에서 **광고 단위 → 배너** → 이름 `가계부 하단 배너` → 만들기
3. 나오는 ID 4개를 GitHub에 넣기: `ohsangplay/onehouse` → Settings → Secrets and variables → Actions → **Variables** 탭 → New repository variable (비밀값이 아니라서 Secrets가 아니라 Variables예요)

| Name | 값 | 모양 |
|---|---|---|
| `BUDGET_ADMOB_APP_ID_IOS` | iOS 앱의 **앱 ID** | `ca-app-pub-1234567890123456~1111111111` (물결 ~) |
| `BUDGET_ADMOB_BANNER_IOS` | iOS 배너의 **광고 단위 ID** | `ca-app-pub-1234567890123456/2222222222` (빗금 /) |
| `BUDGET_ADMOB_APP_ID_ANDROID` | Android 앱의 앱 ID | `ca-app-pub-…~…` |
| `BUDGET_ADMOB_BANNER_ANDROID` | Android 배너의 광고 단위 ID | `ca-app-pub-…/…` |

4. AdMob → **결제** 정보(지급 받을 계좌·세금 정보)는 수익이 쌓이기 전까지만 넣으면 돼요.
5. **app-ads.txt**: AdMob → 앱 → app-ads.txt 설정에 나오는 한 줄을 개발자 웹사이트 도메인 루트에 올려야 광고가 제대로(더 많이) 나와요. 스토어의 개발자 웹사이트/마케팅 URL을 `https://ohsangplay.com`으로 두고 `https://ohsangplay.com/app-ads.txt`에 올리는 걸 추천해요. 출시 뒤에 해도 돼요.
6. 내 폰에서 실제 광고를 반복해서 누르면 계정이 정지될 수 있어요. 확인할 땐 AdMob → 설정 → **테스트 기기**에 내 폰을 등록하세요.


## 1. 업로드 키·빌드

`ohsangplay/onehouse` 저장소는 가계부·메모가 Secrets를 같이 써요. 메모 때 넣은 업로드 키 Secrets(`ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`)가 있으면 그대로 써요. 아직 없으면 `한지붕메모-playstore-등록정보` 1번대로 만들어 넣어 주세요. 키 하나로 두 앱을 서명해도 돼요(Play는 앱마다 업로드 키를 따로 기억해요).

**빌드**: Actions → **Android 빌드 (Play 스토어용 AAB)** → Run workflow → 앱 **budget**, Play 업로드 **none**
- 5~10분 뒤 실행 화면 아래 **Artifacts → budget-aab**를 내려받아 압축을 풀면 `app-release.aab`가 있어요.
- 휴대폰에 바로 깔아 보려면 **Artifacts → budget-apk**를 받아 설치하면 돼요.
- 실행 요약에 "업로드 키로 서명해요"가 떠야 해요.
- 앱은 운영 서버 `https://api.ohsangplay.com/onehouse/budget`에 붙어요 (빌드에 기본값으로 들어가 있음).

**자동 업로드** (처음 AAB를 6번에서 직접 올린 뒤부터): 같은 워크플로에서 Play 업로드 **alpha**(비공개 테스트) 또는 **internal**(내부 테스트)
- 필요한 것: `PLAY_SERVICE_ACCOUNT_JSON` Secret, 그리고 Play Console에서 서비스 계정에 **한지붕 가계부** 앱 권한(테스트 트랙 출시·관리) 추가
  - 서비스 계정 만드는 법은 `한지붕메모-playstore-등록정보` 1-1번과 같아요. 메모 때 만들었으면 Play Console → 사용자 및 권한 → 서비스 계정 → **앱 권한에 한지붕 가계부만 추가**하면 돼요.
- 빌드한 AAB가 그 트랙에 **초안**으로 올라가요. Play Console에서 출시 노트를 넣고 **검토를 위해 전송**을 누르면 끝이에요.

   ```
   첫 버전을 출시했어요. 초대코드 하나로 가족과 함께 쓰는 가계부, 달력과 카테고리 필터로 한 달 지출을 한눈에 확인해 보세요.
   </ko-KR>
   ```
4. **검토를 위해 전송** → 보통 1~7일
5. 출시 후 서버 `wrangler.toml`의 `PLAY_STORE_URL`(App Store는 `APP_STORE_URL`)에 스토어 주소를 넣고 배포하면 안내 페이지 버튼이 링크로 바뀌어요.

## 자주 걸리는 부분

- **개인정보처리방침의 개발자명**: 방침의 운영자 칸에 `오상플레이 (Google Play 개발자명 "오상")`로 적혀 있어요. 개발자 계정 이름이 다르면 `server/src/pages/privacy.ts`를 고쳐서 배포해 주세요.
- **금융 카테고리 앱 심사**: 금융 카테고리라도 실제 금융 서비스가 없으면 추가 서류는 필요 없어요. 나중에 카드 문자 자동입력(알림 읽기)을 넣으면 권한 선언과 데이터 보안을 같이 바꿔야 해요.
- **데이터 보안과 실제 동작이 다르면 거절돼요**: AdMob 항목(위 3번)을 빠뜨리면 "데이터 보안 양식 불일치"로 거절될 수 있어요. 분석 SDK를 넣거나 수집 항목이 바뀌면 데이터 보안과 방침을 같이 바꿔야 해요.
- **광고 정책**: 광고가 버튼에 붙어 실수로 눌리게 하면 AdMob 정책 위반이에요. 배너는 버튼 아래 따로 떨어져 있어요.
- **버전 코드**: 같은 번호는 다시 못 올려요. 워크플로를 다시 실행하면 자동으로 올라가요.
